# Module: wasm

**Role:** `cmd/wasm` is the library's WebAssembly entrypoint: thin `syscall/js` glue exposing the root package's `Parse` (via `load`), `SerializeDef` (via `save`), and `ResolveAnimationFrame` (via `resolveAnimationFrames`) to a browser or any JS host as global functions, so a consumer can load, edit, and animate a MUGEN/Ikemen stage without a Go toolchain of its own. It carries no logic beyond argument conversion, calling into `stage`, and marshaling results to JS — all real behavior lives in the root package, unit-tested independently.
**Files:** `cmd/wasm/main.go`, `cmd/wasm/smoke.mjs`, `cmd/wasm/testdata/` (its own fixture `.def` file for `smoke.mjs`)
**Exports (JS, not Go):**
- `globalThis.OpenKakutouStage.load(defBytes)` — one `Uint8Array` argument, returns `{ stage: string|null, error: string|null }` (exactly one non-null)
- `globalThis.OpenKakutouStage.save(originalDefBytes, editedStageJSON)` — `originalDefBytes` a `Uint8Array` of the `.def` file's own previously loaded bytes (empty for a brand new stage), `editedStageJSON` a JSON string matching `load`'s own `stage` shape; returns `{ bytes: Uint8Array|null, error: string|null }` — `bytes` byte-exact to the original when nothing really changed, freshly generated valid text otherwise
- `globalThis.OpenKakutouStage.resolveAnimationFrames(requestsJSON)` — one JSON string argument: an array of `{ animation, elapsedTicks }` requests (`animation` is the same shape `load`'s own `stage.animations[actionNumber]` exposes, or `null`); returns `{ sprites: [{group,image}]|null, error: string|null }` — one resolved sprite per request, same order, a `null`/malformed `animation` resolving to the blank sentinel rather than an error

**Depends on:** root package (`stage.Parse` for `load`, `stage.SerializeDef` for `save`, `stage.ResolveAnimationFrame` for `resolveAnimationFrames`, see `modules/root.md`)

**Design decision:** `main.go` is build-tag gated (`//go:build js && wasm`), so it is invisible to a normal host `go build ./...`/`go test ./...` — only `GOOS=js GOARCH=wasm go build ./cmd/wasm` compiles it. Every exposed function never lets an internal panic escape to the JS caller (a `recover()` at each callback boundary reports it as `error` instead) and never leaves the module in a broken state after an error — the next call is handled independently. Mirrors the sibling `character` repo's own `cmd/wasm` shape exactly, adapted from four file formats down to `stage`'s single `.def` format — see `.vibe/decisions/005-wasm-entrypoint-mirrors-character-load-save-shape.md`. `smoke.mjs` is a Node.js verification harness (loads the built `.wasm` via `wasm_exec.js`, the same way a browser would) — it is not a `go test` file since `syscall/js` code cannot run under the plain Go toolchain, and doubles as a minimal JS usage example for every global. `save` delegates entirely to the root package's `SerializeDef` (byte-exact-when-unmodified, fresh-serialize-when-edited), wrapping the result in a `saveResult(fileBytes []byte, err error) map[string]any` helper mirroring `loadResult`'s own `{ ..., error }` pattern. `resolveAnimationFrames` batches every animated element needing resolution on a given rendered frame into one call rather than one call per element, to keep the fixed per-crossing JS↔WASM overhead from multiplying by element count on every animation frame — see `.vibe/decisions/007-batched-resolve-animation-frames-wasm-call.md`. Sprite pixel resolution (unlike `character`'s `resolveSprites`) is not exposed here yet — only sprite *references* travel through `load`'s JSON, see `docs/wasm.md`'s "Not yet exposed" section and follow-up backlog item.
