# Module: wasm

**Role:** `cmd/wasm` is the library's WebAssembly entrypoint: thin `syscall/js` glue exposing the root package's `Parse` (via `load`) and `SerializeDef` (via `save`) to a browser or any JS host as global functions, so a consumer can load and edit a MUGEN/Ikemen stage without a Go toolchain of its own. It carries no logic beyond argument conversion, calling into `stage`, and marshaling results to JS — all real behavior lives in the root package, unit-tested independently.
**Files:** `cmd/wasm/main.go`, `cmd/wasm/smoke.mjs`, `cmd/wasm/testdata/` (its own fixture `.def` file for `smoke.mjs`)
**Exports (JS, not Go):**
- `globalThis.OpenKakutouStage.load(defBytes)` — one `Uint8Array` argument, returns `{ stage: string|null, error: string|null }` (exactly one non-null)
- `globalThis.OpenKakutouStage.save(originalDefBytes, editedStageJSON)` — `originalDefBytes` a `Uint8Array` of the `.def` file's own previously loaded bytes (empty for a brand new stage), `editedStageJSON` a JSON string matching `load`'s own `stage` shape; returns `{ bytes: Uint8Array|null, error: string|null }` — `bytes` byte-exact to the original when nothing really changed, freshly generated valid text otherwise

**Depends on:** root package (`stage.Parse` for `load`, `stage.SerializeDef` for `save`, see `modules/root.md`)

**Design decision:** `main.go` is build-tag gated (`//go:build js && wasm`), so it is invisible to a normal host `go build ./...`/`go test ./...` — only `GOOS=js GOARCH=wasm go build ./cmd/wasm` compiles it. Both exposed functions never let an internal panic escape to the JS caller (a `recover()` at each callback boundary reports it as `error` instead) and never leave the module in a broken state after an error — the next call is handled independently. Mirrors the sibling `character` repo's own `cmd/wasm` shape exactly, adapted from four file formats down to `stage`'s single `.def` format — see `.vibe/decisions/005-wasm-entrypoint-mirrors-character-load-save-shape.md`. `smoke.mjs` is a Node.js verification harness (loads the built `.wasm` via `wasm_exec.js`, the same way a browser would) — it is not a `go test` file since `syscall/js` code cannot run under the plain Go toolchain, and doubles as a minimal JS usage example for both globals. `save` delegates entirely to the root package's `SerializeDef` (byte-exact-when-unmodified, fresh-serialize-when-edited), wrapping the result in a `saveResult(fileBytes []byte, err error) map[string]any` helper mirroring `loadResult`'s own `{ ..., error }` pattern. Sprite pixel resolution (unlike `character`'s `resolveSprites`) is not exposed here yet — only sprite *references* travel through `load`'s JSON, see `docs/wasm.md`'s "Not yet exposed" section and follow-up backlog item.
