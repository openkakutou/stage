## Observed patterns
- Tests are co-located with source as `*_test.go`, named `Test<Subject>_<Expectation>` (e.g. `TestStage_ZeroValue_IsUsableWithNoElements`)
- Pure-data read-path types carry a doc comment on every exported field citing its exact `.def` section/key origin
- Root-level aggregate types (`Stage` and everything it composes) carry camelCase `json` tags, matching the JSON contract convention `character`'s own WASM-facing types (`air.Frame`, `cns.StateDef`, `character.Character`) use, since `Stage` is expected to cross a future WASM boundary (backlog item 006) the same way
- Distinct domain concepts that could be confused (camera scroll clamp vs. character movement clamp) are kept as separate Go types rather than one shared type, so misuse is a compile error
- Single dependency: `go.mod` declares `github.com/openkakutou/sff` (a released, tagged version — currently v0.2.0), stdlib otherwise
- `SpriteResolver` mirrors `character`'s `air.SpriteResolver` shape exactly (`NewSpriteResolver(groups)` indexing by key, a `Resolve` method returning a descriptive error on a miss) but takes a `SpriteRef` rather than a whole element, since only `BGElementNormal`/`BGElementParallax` elements carry one — see `.vibe/decisions/002`
- `Parse` mirrors the `character` repo's `def.Parse`/`cns.Parse` tolerance conventions exactly: unrecognized sections/keys are skipped rather than erroring, a non-key-value content line inside a known section is ignored, comments (`;`) are stripped before parsing, and only a malformed section header, an invalid number, or a reader failure produce a line-numbered error
- A `[BG <name>]` section header is recognized by a case-insensitive `bg` keyword prefix followed by whitespace, distinguishing it from single-word sections like `[BGDef]` that share the same first two letters
- The write path mirrors `character`'s own `def` package split exactly: `Serialize` always writes fresh text (a semantic round trip through `Parse`, not byte-exact preservation), while `Document`/`ParseDocument` is the separate format-preserving type guaranteeing a byte-exact round trip for *unmodified* content only, by retaining the parsed source bytes verbatim rather than attempting per-line reconciliation around an edit
- `Serialize` omits `BGdef.SpriteFile` when empty (the one optional string field) but always writes every numeric field, since a numeric zero (e.g. `ZOffset` `0`, an element's `Delta` `0,0`) is meaningful `.def` data rather than an "unset" sentinel — an element's `Sprite` is written only for `BGElementNormal`/`BGElementParallax` and its `ActionNumber` only for `BGElementAnim`, mirroring which field `Parse` itself populates per `Type`
- `BGdef.ModelFile`'s emptiness is the single source of truth for "is this stage 3D": `Serialize` gates every 3D-only section/key (`[Model]`, `[Scaling]`, `Camera`'s `Near`/`Far`/`FOV`/`YShift`, `PlayerInfo`'s `TopBound`/`BottomBound`/`PlayerStartZ`) on it, rather than a separate `Is3D` flag that could disagree with it — see `.vibe/decisions/003`
- `BGAnimation`/`BGAnimFrame` mirror `character`'s `air.Animation`/`air.Frame` shape (frame sequence + `LoopStart`) rather than being folded onto `BGElement`, since `Parse` doesn't read `[Begin Action N]` blocks yet — keeping the type additive and honest about what's wired up, deferred to a follow-up item — see `.vibe/decisions/004`
- `ResolveParallaxPosition`/`ResolveAnimationFrame` are pure functions (no method receiver, no state) returning a defined fallback (a blank `SpriteRef` sentinel, `{-1,-1}`, mirroring `air.Frame.IsBlank()`'s convention) for malformed input instead of an error or a panic, distinct from `SpriteResolver.Resolve`'s error-returning convention for a genuinely missing sprite reference — the two failure shapes serve different callers (a malformed *self-describing* animation vs. a reference to sprite data that must be loaded externally)
