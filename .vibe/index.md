## Observed patterns
- Tests are co-located with source as `*_test.go`, named `Test<Subject>_<Expectation>` (e.g. `TestStage_ZeroValue_IsUsableWithNoElements`)
- Pure-data read-path types carry a doc comment on every exported field citing its exact `.def` section/key origin
- Root-level aggregate types (`Stage` and everything it composes) carry camelCase `json` tags, matching the JSON contract convention `character`'s own WASM-facing types (`air.Frame`, `cns.StateDef`, `character.Character`) use, since `Stage` is expected to cross a future WASM boundary (backlog item 006) the same way
- Distinct domain concepts that could be confused (camera scroll clamp vs. character movement clamp) are kept as separate Go types rather than one shared type, so misuse is a compile error
- Single dependency: `go.mod` declares `github.com/openkakutou/sff` (once added), stdlib otherwise
- `Parse` mirrors the `character` repo's `def.Parse`/`cns.Parse` tolerance conventions exactly: unrecognized sections/keys are skipped rather than erroring, a non-key-value content line inside a known section is ignored, comments (`;`) are stripped before parsing, and only a malformed section header, an invalid number, or a reader failure produce a line-numbered error
- A `[BG <name>]` section header is recognized by a case-insensitive `bg` keyword prefix followed by whitespace, distinguishing it from single-word sections like `[BGDef]` that share the same first two letters
