# WASM entrypoint mirrors `character`'s `load`/`save` shape and byte-exact-when-unmodified save strategy

**Context:** Backlog item 006 needs a browser-loadable WASM build of this repo's read (`Parse`) and write (`Serialize`/`Document`) surface, for `stage-viewer-web`/`stage-editor` to consume without a Go toolchain — the same problem the sibling `character` repo already solved for `character-viewer-web`/`character-editor`, including the tension between "the save path must reflect an edited in-memory model" and "an unmodified round trip must stay byte-exact" (`character`'s own `.vibe/decisions/028`).

**Decision:** Mirror `character`'s `cmd/wasm/` shape directly, adapted to `stage` having exactly one file format (`.def`) instead of `character`'s four: a build-tag-gated (`js && wasm`) entrypoint exposing a global `OpenKakutouStage` object with `load(defBytes)` (wraps `Parse`, returns `{stage, error}`) and `save(originalDefBytes, editedStageJSON)` (wraps a new root-package `SerializeDef(original []byte, s Stage) ([]byte, error)`, returns `{bytes, error}`). `SerializeDef` reuses `character.SerializeDef`'s exact strategy: parse `original` via `ParseDocument` (skipped when `original` is empty), and if the edited `Stage` — after normalizing nil slices (`Elements`) to empty, so a JSON round trip on the JS side is never spuriously treated as an edit — deep-equals the parsed baseline, write the `Document`'s retained source back out byte-exact; otherwise fall back to the existing fresh-write `Serialize`. `SerializeDef` is plain Go, fully unit-tested via `go test`, independent of the WASM glue itself (which is instead verified by a Node.js smoke test, `syscall/js` code being untestable under the plain toolchain). The release workflow mirrors `character`'s own `release.yml` step-for-step (same tag trigger, same explicit `permissions: contents: write`, same `go-version-file: go.mod`), with one addition: a fail-fast existence check on `wasm_exec.js`'s source path before copying it, so a future Go toolchain relocation (it already moved once, `misc/wasm/` → `lib/wasm/`, before Go 1.24) fails the build loudly instead of silently shipping a stale or missing file.

**Reason:** `character`'s shape is a proven, working precedent in this same org for the identical problem (byte-exact-when-unmodified vs. reflects-the-edit), so re-deriving it from scratch would risk a subtly different, undocumented contract for no benefit — consistency here is what lets `stage-viewer-web`/`stage-editor` reuse `character-viewer-web`/`character-editor`'s own WASM-bridge patterns directly. Reusing the format's own existing `Document`/`Serialize` write paths (rather than inventing a diff-and-patch regeneration) keeps the same scope boundary `character`'s decision 028 already drew and every `Document` type in this org already documents.

**Rejected alternatives:**
- *A single unified `save` accepting the whole edited `Stage` with no byte-exact case, always fresh-serializing* — rejected: fails the "unmodified round trip stays byte-exact" bar `character`'s own precedent (and this repo's own `Document` guarantee) already sets.
- *Diff-and-patch regeneration of `Document`'s retained source around an edit* — rejected as out of scope, same reasoning `character`'s decision 028 recorded: every `Document` type in this org already declines to solve per-line reconciliation around an edit, and solving it here as a side effect of the WASM item would contradict that repeated stance.
- *A hardcoded Go version in `actions/setup-go` instead of `go-version-file: go.mod`* — rejected: risks pairing `stage.wasm` with a `wasm_exec.js` shim built for a different Go minor version than what actually compiled it, a wasm-specific version-skew bug class `character`'s own workflow already avoids.
