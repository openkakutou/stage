# Data model

The `stage` package (repo root) defines the pure-data, read-path model for a
MUGEN/Ikemen GO stage: what a stage `.def` file describes, before any
parsing exists to populate it (parsing/serialization land with backlog
items 002/003). Every field below cites the exact `.def` section and key it
maps to, so the future parser has an unambiguous target.

A zero-value `Stage` is valid and immediately usable — no nil pointers, no
panics on first access (e.g. ranging over a nil `Elements`).

## `Stage`

The root aggregate: composes stage-level settings, the ordered list of BG
elements/layers, and the two distinct kinds of movement limit a stage
defines.

| Field | Type | Meaning |
|---|---|---|
| `BGdef` | `BGdef` | Stage-level settings (sprite sheet, coordinate space, ground level, camera zoom range) |
| `Elements` | `[]BGElement` | BG elements/layers, in `.def` file order |
| `CameraBounds` | `CameraBounds` | The box the camera's own position is clamped to |
| `StageBoundaries` | `StageBoundaries` | The x-range characters are allowed to move within |

## `BGdef`

Stage-level settings, sourced from the `.def` `[BGDef]`, `[StageInfo]`, and
`[Camera]` sections:

| Field | `.def` origin | Meaning |
|---|---|---|
| `SpriteFile` | `[BGDef]` `spr` | Path to the stage's `.sff` sprite sheet |
| `LocalCoordWidth`, `LocalCoordHeight` | `[StageInfo]` `localcoord` | Coordinate space element positions are expressed in |
| `ZOffset` | `[StageInfo]` `zoffset` | Ground level's vertical distance from the top of the local coordinate space |
| `ZoomOut`, `ZoomIn` | `[Camera]` `zoomout`/`zoomin` | Camera's zoom scale range |

## `BGElement`

A single `[BG element_name]` section — one layer of the stage's background.
`Type` selects which of the format's three element kinds it is; each kind
uses a different subset of the remaining fields.

| Field | `.def` origin | Meaning |
|---|---|---|
| `Name` | `[BG <name>]` section header | The element's section name |
| `Type` | `type` | `BGElementNormal` (static sprite), `BGElementParallax` (depth-scrolling), or `BGElementAnim` (`.air`-driven) |
| `Sprite` | `spriteno` | Static sprite reference (`SpriteRef{Group, Image}`) — used by Normal/Parallax, zero-value for Anim |
| `ActionNumber` | `actionno` | `.air` action number this element plays — used only by Anim |
| `LayerNo` | `layerno` | Draw order relative to characters: `0` behind, `1` in front |
| `StartX`, `StartY` | `start` | Starting position, in local coordinate units |
| `DeltaX`, `DeltaY` | `delta` | Scroll ratio per unit of camera movement (fractional — this is how parallax depth is expressed) |
| `TileX`, `TileY` | `tile` | Tiling repetition per axis: `0` none, `1` infinite, `>1` a fixed count |
| `TileSpacingX`, `TileSpacingY` | `tilespacing` | Pixel gap between repeated tiles |

`SpriteRef{Group, Image}` mirrors `.def`'s `spriteno` pair — the same
(group, image) addressing scheme `sff` sprite sheets use.

## `CameraBounds` vs `StageBoundaries`

These are kept as two distinct Go types on purpose — they clamp two
different things, sourced from two different `.def` sections, and mixing
them up is a compile error rather than a silent bug:

| Type | `.def` section | Constrains | Fields |
|---|---|---|---|
| `CameraBounds` | `[Camera]` `boundleft`/`boundright`/`boundhigh`/`boundlow` | The camera's own scroll position | `Left`, `Right`, `High`, `Low` |
| `StageBoundaries` | `[PlayerInfo]` `leftbound`/`rightbound` | Where characters may move (x-axis only) | `Left`, `Right` |

`StageBoundaries` intentionally has no vertical (top/bottom) fields:
mainline MUGEN/Ikemen GO defines no vertical movement bound for characters.
See `.vibe/decisions/001-stage-boundaries-model-left-right-only.md` for the
full reasoning.

## JSON shape

Every exported field carries a `json` tag (camelCase), matching the
convention `character`'s own WASM-facing types (`air.Frame`, `cns.StateDef`,
`character.Character`) already use — `Stage` is this repo's equivalent
root aggregate, and is expected to be JSON-marshaled across a future WASM
boundary (backlog item 006) the same way.
