# Testing

## Running the suite

```sh
go test ./...
```

Standard library `testing`, no external test framework. Test files are
co-located with the source they test, one file per source file
(`parser_test.go` next to `parser.go`, and so on).

## Fixture-driven tests against real files

Three real, unmodified stage `.def` files are vendored under `testdata/`
(see `testdata/README.md`): `mugen-2d-stage.def`, a real MUGEN 1.1 stage
with no 3D content; `ikemen-go-3d-model-stage.def`, a real Ikemen GO 3D
model-based stage (`[Model]`, `fov`, a stage-portrait animation block); and
`mugen-nondefault-scale-stage.def`, a real stage authoring hi-res BG
sprite art and relying on `[StageInfo]`'s `xscale`/`yscale` to scale it
down at draw time. `corpus_fixtures_test.go` exercises `Parse`,
`Document`'s byte-exact round trip, and `SerializeDef`'s
byte-exact-on-unmodified-save round trip against all three — real-world
comment placement, spacing, and section ordering that hand-built
synthetic fixtures don't reliably reproduce.

## Real-file corpus compatibility scan

`corpus_compat_test.go`'s `TestCorpusCompat_RealDefFiles_ParseSuccessRate`
scans every `.def` file under a local, machine-specific corpus — gated on
the `STAGE_CORPUS_DIR` environment variable, skipped entirely (not failed)
when it's unset, so this repo's normal test run and CI never depend on it.
See `.vibe/fixture-sources.md` for where that corpus lives and how to point
the scan at it. It checks three things per file: `Parse` succeeds,
`Document`'s parse→serialize round trip is byte-exact, and `SerializeDef`'s
save of an unmodified `Stage` is byte-exact. Any failure in any of the
three fails the test loudly — a corpus file hitting an undocumented gap is
caught here, not shipped quietly broken.

This scan found three real parse failures during backlog item 007's own
run — a BG element's tiling setting written as a single shorthand value
instead of a pair, a decimal point on the integer `zoffset` setting, and a
blank timing value on an animation frame line — all fixed rather than left
as gaps, since each has an unambiguous, safe interpretation (see
`.vibe/decisions/008`). The scan now passes at 100% (58/58 files) against
the local corpus.

## Round-trip guarantees

Every write-path type is covered by its own round-trip suite: `Serialize`
(fresh-write, semantic round trip through `Parse`, not byte-exact
preservation) and `Document`/`ParseDocument` (byte-exact for *unmodified*
content, format-preserving around an edit). `SerializeDef` combines both —
byte-exact when the edited `Stage` deep-equals the parsed baseline,
fresh-serialized otherwise — and is the one exercised against both the
real corpus and the vendored fixtures above, since it's the path a real
consumer (`stage-editor`) actually saves through.
